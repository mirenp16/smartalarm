## Automated evidence

`python3 scripts/test.py 3` compiles release and test builds for `fr265s` and
executes 15 native tests per run. The final series, including the sensor-cleanup
fix, passed all 45 test executions on SDK 9.2.0. Both builds completed without
compiler warnings and `git diff --check` passed. Logs are generated in
`bin/validation/tests-1.log` through `tests-3.log`.
The suite uses synthetic sensor inputs through production ingestion methods;
it does not duplicate the algorithm in Python. The only detector setup helper
is excluded from release builds by the `testSupport` annotation.

The runner checks the complete success footer and expected test count because
the installed SDK's `monkeydo` can return exit code 1 even when every test passes.
A missing footer, test failure, timeout, or incomplete run fails validation.
The runner retries startup connection failures because macOS can return from
launching the simulator before its listener is ready. It never retries a failing test.

## Limits and device checks

No review or simulator suite can establish that software has no bugs. These
tests do not validate physical sensor accuracy, overnight battery consumption,
sound/vibration on the watch, or every UI transition.

Existing calendar limitations remain: repeating wake windows are evaluated from
the current day, so the portion before midnight is unavailable; only one alarm
can ring at once; calendar calculations use 24-hour day offsets, so daylight
saving/time-zone changes need separate validation. One-time alarms store an
absolute timestamp. These are not covered by the repeat-mask tests as clock-change
scenarios. They do not explain a normal 6:00 am alarm on September 24.

On the watch, verify a short alarm while walking before its window; then verify
an alarm with no early-wake evidence reaches its deadline, snooze works, the
passcode dismisses it, and an unfinished Active Alarm exit prompt is interrupted
by a due alarm. Finally test overnight with the usual settings and note the
heart-rate status, target/window, actual firing time, and any app interruption.
Keep a native Garmin backup alarm during that validation.
